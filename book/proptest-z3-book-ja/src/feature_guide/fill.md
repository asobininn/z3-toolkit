# fill と Solved

`fill`で骨格の Strategy と名前の候補と規則をまとめて、穴を埋めた入力の Strategy にします。生成される値は `Solved` です。

```rust
proptest! {
    #[test]
    fn defined_names_resolve(s in program().fill(names(), |binds| bound(binds, VAR))) {
        prop_assert_eq!(undefined_refs(&s.text), vec![], "{:?}", s);
    }
}
```

## 解き方を選ぶ

`fill_with` を使用すると、穴の埋め方を選択できます。既定では `fill` は `Fill::Greedy` を使用します。

| 解き方 | 内容 |
| --- | --- |
| `Fill::Greedy`(既定) | ヒントを仮定として解き、制約と衝突したら、衝突したヒントのうち最後のものを捨てて解き直す |
| `Fill::Optimal` | 守れるヒントの数が最大になるように解く |

どちらの解き方でも、同じ骨格と[ヒント](./space.md#ヒント)からは同じ結果が得られます。縮小の途中で同じ入力を解き直しても、結果は変わりません。

- `Fill::Greedy` は速いのが利点です。ただし、捨てるヒントの選び方が最適とは限らないので、`Fill::Optimal` より多くのヒントを捨てることがあります。

- `Fill::Optimal` はヒントにできるだけ忠実です。その分、穴が多いと遅くなります。

基本は `Fill::Greedy` を使用し、生成される名前の偏りが気になる場合に `Fill::Optimal` を試してください。

## 縮小

テストが失敗すると、proptest は入力を縮小します。 proptest-z3 の縮小は、構造・ヒント・名前の候補を縮めながら、規則を満たす入力だけを試します。

- 縮めた入力が規則を満たせないときは、別の縮め方を探す
- 解いた結果が以前に試したものならば、テストを呼ばない
- 縮めた入力が以前と同じならば、解き直さない

縮小は、これ以上縮まなくなるまで繰り返すことはしません。原因が読み取れる大きさまで縮めば十分という方針です。

縮小では入力が変わるたびに Z3 が呼ばれるので、縮小には通常の proptest より時間がかかります。

## Solved: 埋めた結果を使用する

`Solved` は穴を埋めた結果です。Z3 の型を含まないので、テストの本体では Z3 を意識する必要はありません。

### テキスト

`s.text` は、穴を埋めた文字列です。テスト対象にはこれを渡します。

### 穴

| 書き方 | 内容 |
| --- | --- |
| `s.holes()` | テキストに現れる順の穴。`(Hole, &FilledHole)` の列 |
| `s.events()` | [評価順](./frag.md#評価順)の穴。`&[Hole]` |
| `s.hole(h)` | 穴 h の情報(`&FilledHole`) |
| `s.name(h)` | 穴 h に入った名前。`s.hole(h).name` と同じ |
| `s.span(h)` | 穴 h の、テキスト中の位置。`s.hole(h).span` と同じ |
| `s.target(h)` | 参照 h が指す定義の穴(`Option<Hole>`) |

`FilledHole` は、次のフィールドを持ちます。

| フィールド | 内容 |
| --- | --- |
| `space` | 名前空間 |
| `role` | 役割(`Def` / `Use` / `Kill`) |
| `name` | 入った名前 |
| `span` | テキスト中の位置(バイト) |

`s.target(h)` が返すものは、穴の役割で決まります。定義へジャンプ、参照検索、rename などの検査で役立ちます。

| 穴 | 返すもの |
| --- | --- |
| `Use` | その名前が指す、見えている定義 |
| `Kill` | 削除する定義 |
| 見えていない参照、定義 | `None` |

### ラベル

| 書き方 | 内容 |
| --- | --- |
| `s.marks::<L>()` | `mark` で記録された `(穴, ラベル)` の列 |
| `s.labels::<L>()` | 記録されたラベルの列 |
| `s.has(kind)` | `kind` が記録されたか |

使い方は [ラベル](./labels.md) を参照してください。

### 表示

`Solved` の `Debug` は、行番号を付けたテキストと、記録された `mark` とラベルの一覧を表示します。反例の表示に向いています。

```text
Solved{
  0| let b
  1| let a = a
 marks: Undefined @ 14..15 `a`
}
```

proptest は縮小した反例を `Debug` で表示するので、テストが失敗するとこの形で表示されます。`prop_assert!` のメッセージに `{:?}` で `s` を渡しておくと、アサーションの失敗にも同じ表示が付きます。

行番号を付けたテキストだけが欲しいときは、`s.numbered()` を使います。戻り値は `String` で、`mark` とラベルは含みません。
